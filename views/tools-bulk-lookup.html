What bulk IP lookup is for

Looking up one address at a time is fine until you have a log file. Bulk lookup takes a list and returns the same geolocation record for every entry in one pass, so you can work with the result as a table instead of a browser tab per address.

The typical inputs are access logs, firewall or fail2ban blocklists, mail server rejection lists, CDN reports, and analytics exports. The typical question is one of: where is this traffic coming from, which networks does it belong to, and is any of it coming from hosting infrastructure rather than real users.

What you get for each address

  • Location — country, region and city where available, at city-level accuracy at best.
  • Network — the ISP or organisation name and the ASN that announces the address.
  • Timezone — the IANA zone for the resolved location.
  • Classification — whether the address looks residential, mobile, or datacentre, and whether it appears to be a VPN, proxy or Tor exit.

Every row links through to the full report for that address, which adds reverse DNS, the registry record, the announced range, and the abuse contact.

Limits and how to work within them

A single run accepts up to 100 addresses, and the endpoint is rate limited to 30 requests per minute per client. Those limits exist because each lookup does real work on this server, and because the service is free and unauthenticated.

If you have more than 100 addresses, the sensible approach is to deduplicate first. Log files are extremely repetitive — a few thousand log lines usually contain only a few dozen distinct addresses. On a Unix-like system:

awk '{print $1}' access.log | sort -u > ips.txt
wc -l ips.txt

For anything genuinely larger, use the JSON API directly and batch it yourself. The POST /api/bulk endpoint takes the same 100-address maximum per call, so a script that chunks a list into hundreds and paces itself against the rate limit will get through an arbitrarily large file without any special access.

Exporting the results

Results export as CSV or JSON. The CSV carries one row per address with the columns ip, city, region, country, countryCode, isp, asn, timezone, riskLabel and error, quoted where a value contains a comma or a newline. That opens cleanly in a spreadsheet and imports cleanly into a database.

Addresses that fail validation or cannot be resolved still appear in the output with the reason in the error column, so a partial failure never silently shortens your result set. Check the row count against your input count if that matters to you.

Reading the results honestly

Two cautions worth taking seriously before you act on a table of geolocation data.

First, city-level results are approximate. They reflect where a provider registered or routes an address, not where a person is sitting, and mobile carriers in particular route large subscriber populations through a small number of gateways. Country is usually reliable; city frequently is not. There is more detail in how accurate is IP geolocation.

Second, the VPN and datacentre classification is heuristic. It is inferred from the ASN, the organisation name and reverse DNS patterns, not from a commercial threat feed. It will flag residential ISPs that also sell hosting, and it will miss VPN operators running on residential address space. Use it as a prompt to look closer, not as a verdict. The VPN and proxy check shows the reasoning for a single address.

Frequently asked questions

Is there a limit on how many IPs I can look up?

100 addresses per run through this page, and 30 requests per minute per client against the API. Deduplicate your list first — it usually cuts the volume dramatically — or chunk it against the API for larger jobs.

Can I upload a CSV or log file?

Not directly. Extract the address column first and paste the values in, one per line or comma separated. On Unix-like systems awk '{print $1}' access.log | sort -u handles most log formats.

Do I need an API key?

No. There is no key, no signup and no quota beyond the published rate limit. See the API documentation for the endpoint details.

Are my uploaded addresses stored or logged?

Bulk requests are served and discarded. Request logging records the endpoint, status and timing rather than the address list. The Privacy Policy sets out what is retained.

Why does an address show no city?

Either the offline database has no city record for that range, or the address is private, reserved, or bogon space that cannot be geolocated at all. Private ranges such as 10.0.0.0/8 and 192.168.0.0/16 never resolve to a public location.
